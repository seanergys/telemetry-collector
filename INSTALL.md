# Installation

## Install with Spack

Use the `telemetry-collector` package from Seanerstack. Its recipe installs the
collector and its plugins and resolves Seanerbus C++, Cap’n Proto, yaml-cpp,
Net-SNMP, spdlog, fmt, and UUID support through Spack.

### Seanerstack setup

Use Seanerstack’s [getting started guide](https://gitlab.seanergys.fz-juelich.de/software/seanerstack/-/blob/main/docs/tutorials/getting-started.md)
to install Seanerstack, set up Spack, and activate the isolated shell. For
private GitLab or build-cache access, see the
[secrets guide](https://gitlab.seanergys.fz-juelich.de/software/seanerstack/-/blob/main/docs/how-to/create-a-secrets-file.md).

### Install the packaged version

Run this from an activated Seanerstack shell.

```sh
spack install telemetry-collector@main
```

### Build from a local checkout

For development, run these commands from the root of the telemetry collector
checkout in an activated Seanerstack shell.

```sh
spack env activate "$(seanerstack paths env --package telemetry-collector)"
spack develop --path "$PWD" telemetry-collector@main
spack concretize -f
spack install
```

The environment records the checkout path for subsequent builds. The Spack
recipe applies its source patches to the checkout during a development build.
Run `spack install` again after editing the source, and reconcretize when
dependency requirements change.

### Test the installed Spack package

Run the recipe's smoke tests from the same Spack session. They check the
installed executable's usage message and verify that the installed plugins can
be loaded without a running broker.

```sh
spack test run telemetry-collector@main
spack test results --logs -- telemetry-collector@main
```

For the repository’s CTest suites and combined report, follow
[Running and testing locally](RUN.md#running-and-testing-locally). To run the
service-backed plugin tests against the Spack installation, use a CMake
build with compatible SeanerBUS C++ dependencies and set
`TC_PLUGIN_TEST_INSTALL_PREFIX` to the prefix returned by
`spack location -i telemetry-collector@main` when configuring the plugin tests.

### Find the installation and run the collector

Keep the development environment active if you built from a checkout. Use
Spack to locate the installed package.

```sh
tc_prefix="$(spack location -i telemetry-collector@main)"
```

The executable is at `bin/telemetry_collector` under that prefix. The generated
configuration and plugin YAML files are in `etc/telemetry_collector`. The main
configuration contains absolute paths to the installed plugins and their YAML files.

Copy the main configuration to a writable location, set `seanerbus.url` to
your broker, and review the enabled plugins and their configuration paths.

```sh
cp -i "$tc_prefix/etc/telemetry_collector/config.yaml" ./telemetry_collector.yaml
```

After editing `telemetry_collector.yaml`, start the collector.

```sh
"$tc_prefix/bin/telemetry_collector" ./telemetry_collector.yaml
```

If you customize a plugin YAML file, copy it to a writable location and update
the corresponding `config` path in `telemetry_collector.yaml`.

## Install manually with CMake

### Prerequisites

Install a C++20 compiler, CMake 3.21 or newer, a build tool such as Make or
Ninja, and `pkg-config`. CMake 3.21 enables the JUnit reports described below.

Install the development files for Seanerbus C++, Cap’n Proto, UUID, yaml-cpp,
fmt, spdlog built with external fmt, and Net-SNMP for the SNMP plugin. Use a
Spack or system prefix that provides compatible versions of Seanerbus C++,
Cap’n Proto, and fmt. The [GitLab CI configuration](.gitlab-ci.yml) shows how
to build Seanerbus C++ from source with the schema revision used in CI.

Install GoogleTest before configuring the manager and configuration suites.
Python 3.6 or newer enables per-case logs in those reports and is required
for the service-backed plugin tests.
For dependencies installed outside the standard search paths, add their
installation prefixes to CMake’s `CMAKE_PREFIX_PATH`. You can also pass
`-DSEANERBUS_ROOT=/path/to/seanerbus` and
`-DCAPNP_ROOT=/path/to/capnproto` for those two packages.

### Build dependencies from source

Use these recipes if you need to build the dependencies from the original
manual procedure. Start in the collector checkout and use a fresh dependency
directory. The compiler module used on ICE2 was
`gcc/14.2.0-gcc-13.2.0-57z6vik`. On other systems, select an available C++20
compiler.

```sh
tc_deps="$PWD/manual-deps"
tc_capnp_prefix="$tc_deps/capnp-0.8"
mkdir -p "$tc_deps/src"
```

**Cap’n Proto 0.8.0**

Use 0.8.0 with the older Seanerbus checkout that expects headers generated by
that version. For a newer Seanerbus checkout, use the Cap’n Proto version
required by that checkout and set `tc_capnp_prefix` to its installation
prefix before building Seanerbus.

```sh
(
  cd "$tc_deps/src" &&
  curl -fLO https://capnproto.org/capnproto-c++-0.8.0.tar.gz &&
  tar -xzf capnproto-c++-0.8.0.tar.gz &&
  cd capnproto-c++-0.8.0 &&
  ./configure --prefix="$tc_capnp_prefix" CXXFLAGS=-fPIC CFLAGS=-fPIC &&
  make -j4 &&
  make install
)
export PATH="$tc_capnp_prefix/bin:$PATH"
export PKG_CONFIG_PATH="$tc_capnp_prefix/lib/pkgconfig${PKG_CONFIG_PATH:+:$PKG_CONFIG_PATH}"
export LD_LIBRARY_PATH="$tc_capnp_prefix/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
```

**yaml-cpp**

```sh
git clone https://github.com/jbeder/yaml-cpp.git "$tc_deps/src/yaml-cpp" &&
cmake -S "$tc_deps/src/yaml-cpp" -B "$tc_deps/src/yaml-cpp/build" \
  -DCMAKE_INSTALL_PREFIX="$tc_deps/yaml-cpp" \
  -DCMAKE_BUILD_TYPE=Release \
  -DYAML_BUILD_SHARED_LIBS=OFF \
  -DCMAKE_POSITION_INDEPENDENT_CODE=ON &&
cmake --build "$tc_deps/src/yaml-cpp/build" --parallel 4 &&
cmake --install "$tc_deps/src/yaml-cpp/build"
```

**Net-SNMP 5.9.4**

```sh
(
  cd "$tc_deps/src" &&
  curl -fLO https://sourceforge.net/projects/net-snmp/files/net-snmp/5.9.4/net-snmp-5.9.4.tar.gz &&
  tar -xzf net-snmp-5.9.4.tar.gz &&
  cd net-snmp-5.9.4 &&
  ./configure --prefix="$tc_deps/net-snmp" \
    --with-defaults --disable-agent --disable-manuals &&
  make -j4 &&
  make install
)
```

**Seanerbus C++**

For the older dataplane layout, point `tc_seanerbus_src` at
`dataplane/seanerbus/bindings/cpp`. Prepare the schema and bundled fmt
sources required by that checkout first. Put the matching `capnp` executable
on `PATH` and use a fresh build directory so the generator and libraries come
from the same version.

```sh
tc_seanerbus_src=/path/to/dataplane/seanerbus/bindings/cpp
cmake -S "$tc_seanerbus_src" -B "$tc_deps/seanerbus-build" \
  -DCMAKE_INSTALL_PREFIX="$tc_deps/seanerbus" \
  -DCMAKE_PREFIX_PATH="$tc_capnp_prefix" \
  -DCMAKE_POSITION_INDEPENDENT_CODE=ON &&
cmake --build "$tc_deps/seanerbus-build" --parallel 4 &&
cmake --install "$tc_deps/seanerbus-build"
```

Make these prefixes visible to the collector build. Also add the prefixes for
any other prerequisites installed outside the system search paths.

```sh
export CMAKE_PREFIX_PATH="$tc_deps/seanerbus:$tc_capnp_prefix:$tc_deps/yaml-cpp:$tc_deps/net-snmp${CMAKE_PREFIX_PATH:+:$CMAKE_PREFIX_PATH}"
```

### Configure, build, and install

From the repository root, use a fresh build directory and set the installation
prefix at configure time. The generated configuration uses that prefix for its
absolute plugin and YAML paths.

```sh
cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$PWD/install" \
  -DUSE_SYSTEM_DEPENDENCIES=ON \
  -DDEPENDENCY_PROVIDER_spdlog=spdlog \
  -DBUILD_TESTING=ON
cmake --build build --parallel 4
cmake --install build
```

CMake builds all discovered plugins by default. Use
`-DSELECTED_PLUGINS='mock;sysfs;tester;snmp'` to build a subset, then remove
entries for omitted plugins from your run configuration.

### Test recipes for the CMake build

Run these commands from the repository root after configuring `build`.
GoogleTest must be available when CMake configures the build.

**Run both suites and generate JUnit reports**

```sh
cmake --build build --target run_plugin_manager_tests run_plugin_configuration_tests --parallel 4
```

For the third suite, prepare the broker, naming server, and subscriber as
described in [RUN.md](RUN.md#3-prepare-the-plugin-test-services). Then run:

```sh
cmake --build build --target run_plugin_tests --parallel 4
```

The fixture starts its own services. Leave TCP port `5398` and UDP port
`1161` free, and put `snmpd` and `snmpget` on `PATH` for the SNMP case.
Reinstall after changing the collector or its plugins so the suite tests
the latest binaries.

Open [`build/test-artifacts/report.md`](build/test-artifacts/report.md) for
the combined report. Each suite has a report with its CTest log, JUnit
results, and any available per-case logs or configs. See the
[test directory guide](tests/README.md) for suite descriptions and fixtures.

**Run one suite**

Choose the CMake target for the area you changed. Each target builds its test
binaries and runs its own suite.

```sh
# Manager lifecycle, loading, and status reporting
cmake --build build --target run_plugin_manager_tests --parallel 4

# YAML parsing and plugin configurators
cmake --build build --target run_plugin_configuration_tests --parallel 4

# Installed plugins and local services, after preparing the service executables
cmake --build build --target run_plugin_tests --parallel 4
```

**Find and rerun one case**

After building the test binaries, list the registered names with `ctest -N`.
Use `-R` with a case name or regular expression and `--output-on-failure` to
see the failing test's output.

```sh
ctest --test-dir build -N
ctest --test-dir build --output-on-failure -R 'PeriodicStatusReporting'
ctest --test-dir build --output-on-failure -R '^PluginConfiguration_snmp_missing_required_fields$'
```

### Run the installed collector

Set `tc_prefix="$PWD/install"` and follow the
[run instructions above](#find-the-installation-and-run-the-collector) from
the configuration-copy step. For an example with the local broker, naming
server, and subscriber, see [RUN.md](RUN.md#run-the-services-manually).
